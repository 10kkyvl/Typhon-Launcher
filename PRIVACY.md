# Политика конфиденциальности Typhon

Редакция от 24 августа 2026 года.

Документ описывает, какие данные Typhon хранит на устройстве пользователя и какие передаёт наружу. Описано фактическое поведение текущей версии приложения, а не намерения.

Typhon использует сервисы учётной записи и метаданных. Утверждение «мы не собираем никаких данных» было бы неверным, поэтому ниже приведено разделение: что не покидает устройство, что уходит сервисам Typhon и что уходит третьим сторонам.

## 1. Данные, которые остаются на устройстве

Следующие данные хранятся только локально и сервисам Typhon не передаются:

- **Источники релизов** — адреса добавленных источников и содержимое их фидов. Фид запрашивается напрямую с хоста источника, соединение идёт с устройства пользователя без промежуточных серверов Typhon.
- **Загрузки** — magnet-ссылки, infohash, списки файлов раздачи, содержимое загруженных файлов, история и состояние загрузок.
- **Установки** — пути установки, состав установленных файлов, история установок и удалений, манифесты обновлений.
- **Библиотека** — список игр, пути к исполняемым файлам, время и длительность игровых сессий.
- **Настройки приложения**, включая параметры BitTorrent.
- **Журнал работы** `typhon.log` — остаётся на устройстве и автоматически никуда не отправляется.

Локальное состояние хранится в каталоге `%APPDATA%\Typhon` в файлах `settings.json`, `account.json`, `library.json`, `sources.json`, `downloads.json`, `installations.json`, `removals.json`, `catalog.json`, `match_overrides.json`, а также в подкаталогах `releases/`, `manifests/` и кэше метаданных.

Удаление этого каталога удаляет все перечисленные локальные данные.

## 2. Данные, передаваемые сервисам Typhon

Адрес сервиса задаётся при сборке приложения. Токен доступа передаётся только по HTTPS; исключение сделано только для локального адреса при разработке.

### 2.1. Учётная запись

Приложение может работать без учётной записи, в гостевом режиме. В этом режиме запросы к сервису учётной записи не выполняются, локально хранится только признак гостевого режима.

При использовании учётной записи сервису передаются:

- при регистрации — адрес электронной почты, имя пользователя, отображаемое имя и пароль;
- при входе — имя пользователя либо адрес электронной почты и пароль;
- при работе с профилем — запросы на чтение и изменение профиля, загрузку и удаление аватара.

Токен сессии хранится в системном хранилище учётных данных Windows (Credential Manager), а не в файле настроек.

### 2.2. Метаданные игр

Чтобы показать обложки, описания и год выпуска, приложение обращается к сервису метаданных:

- поиск по названию игры;
- разрешение списка названий в идентификаторы игр;
- получение карточки игры по идентификатору.

Важные особенности, которые следует понимать:

- **Сервису передаётся название игры.** При автоматическом поиске уже установленных игр название формируется из **имени папки на диске**. Если папка названа произвольно, это произвольное название будет отправлено как поисковый запрос.
- **Запросы метаданных содержат токен учётной записи.** Это означает, что сервис технически может связать учётную запись с тем, какие названия игр запрашивались. Запросы метаданных из гостевого режима токена не содержат.
- Сервису метаданных **не** передаются: адреса источников, содержимое фидов, magnet-ссылки, infohash, содержимое загрузок, история загрузок и пути установки.

### 2.3. Чего сервисы Typhon не получают

Проверено по коду текущей версии: адреса добавленных пользователем источников, содержимое фидов источников, magnet-ссылки, infohash раздач, содержимое загружаемых файлов и локальная история загрузок сервисам Typhon **не передаются**.

## 3. Данные, передаваемые третьим сторонам

Эти передачи не связаны с сервисами Typhon.

### 3.1. Хосты источников

При обновлении источника приложение выполняет HTTP-запрос напрямую к хосту, указанному пользователем. Хост источника видит IP-адрес пользователя и факт запроса. Прокси не используется.

### 3.2. Сеть BitTorrent

При загрузке через BitTorrent приложение участвует в работе распределённой сети: включены DHT и обмен списками участников (PEX). Это означает, что **трекеры, узлы DHT и другие участники раздачи видят IP-адрес пользователя и infohash раздачи**. Такое поведение заложено в протокол BitTorrent.

Передача данных другим участникам управляется двумя раздельными настройками, обе по умолчанию выключены:

- «Отдавать во время загрузки» — передача уже полученных частей во время активной загрузки;
- «Раздавать после загрузки» — передача завершённой загрузки после её окончания.

### 3.3. Изображения метаданных

Обложки и скриншоты загружаются приложением напрямую с сети доставки контента поставщика метаданных по адресам, полученным в ответе сервиса метаданных. Владелец этой сети видит IP-адрес пользователя и запрошенные изображения.

### 3.4. Discord

Функция отображения статуса в Discord по умолчанию **выключена**. Если она включена, приложение передаёт данные локальному клиенту Discord через именованный канал операционной системы — по сети со стороны Typhon эти данные не отправляются. Передаются название запущенной игры, округлённая длительность сессии и, при наличии, адрес обложки. Дальнейшая обработка этих данных выполняется клиентом Discord по правилам Discord.

## 4. Телеметрия и отчёты о сбоях

В приложении отсутствуют телеметрия, аналитика и автоматическая отправка отчётов о сбоях. Соответствующих компонентов в коде нет.
