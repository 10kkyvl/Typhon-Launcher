# Typhon Launcher — Test map

What is covered where, how (unit vs integration), and what is not. Snapshot: 2026-09-11; file lists are navigation aids, not exhaustive coverage guarantees. Confirm the selected tests and their assertions in current code. Broad checks when warranted: `go test ./internal/... && CGO_ENABLED=1 go test -race ./internal/... && CGO_ENABLED=1 go test -race -tags devmock ./internal/...`; frontend `cd frontend && npm run check && npm run test`. CI (`.github/workflows/ci.yml`) runs Linux lint/cross-build/devmock guards, macOS plain + race (plain and devmock), Windows tests, and the per-OS lint baseline.

## Conventions that matter

- Tests build services with `NewServiceAt(dir…)` over `t.TempDir()`; never the user's `<ConfigDir>`.
- Package-local `emit()` is a no-op without a Wails app, so services emit safely in tests; some packages expose a swappable `emit` var to record payloads (`download`).
- Seams for tests: `install.Service.prepareRuntime/releaseRuntime` (must be stubbed on macOS or real CrossOver bottles get created), `library.Service.prepare/start/scan/now/shortcuts/saveRoots` (`library.StubLaunch` and `SetCanonicalID` in `export_test.go` for external-package tests of the launch path), `install.Service.roots/freeSpace/runner`, `updates.Service` narrow interfaces (`librarySource`, `releaseSource`, `downloadSource`, `installer`), `download` `engineTorrent` fakes, `relocate.afterCopyBeforeVerify`.
- Build tags: Windows-only tests are `*_windows_test.go` (no tag needed) or `//go:build windows`; macOS-native `darwin && !devmock`; devmock `devmock && !windows`; `smoke` (internet); `release` (`legal_release_test.go`). Full list: `rg -n '^//go:build' internal -g '*_test.go'`.
- Env-gated live tests skip by default; `TYPHON_WINE_LIVE=1` (+ fixture vars), `TYPHON_KEYCHAIN_LIVE=1`, `TYPHON_PE_LIVE`, `TYPHON_LIVE_PICKER_*`, `TYPHON_METADATA_API`/`_TOKEN`, `TYPHON_STEAM_E2E_URL`.
- Traps: forging `worker-<id>-state.json` without the `Run` token hangs `internal/install` ~10 min; `t.Skip`/`t.Fatal` while holding a mutex whose cleanup takes it deadlocks; `chmod`-based permission tests skip as root and on Windows; `installguard/asset/embed_darwin_test.go` fails if the bridge sources changed without `go generate`.
- Contract tests: `uicodes_test.go` in install, download, updates, relocate, sources, metadata, library, settings, catalog, lan, selfupdate, cloudsaves (`TestErrorCodesMatchTheFrontendCatalogs`) assert Go `uierr` codes ⇔ frontend message tables in both directions.

## Cross-cutting gaps

- No automated end-to-end test drives a real Windows elevated install, Windows self-update, or the release pipeline; CI covers compilation and Windows unit tests only.
- Race detector runs only on macOS (plain and devmock) in CI; Windows tests run without `-race`.
- Behaviour that depends on the live backend (metadata, social, sync) is tested against `httptest` fakes; contract drift with `typhon-backend` shows up only in env-gated e2e tests.
- Historical audit findings (`AUDIT_FABLE_5_1.md`, 2026-09-10) require current code and test inspection before deciding whether they are still open; several `audit_regression_test.go` files exist for earlier findings and are the pattern to follow.

To find current files, use `rg --files internal/<package> -g '*_test.go'` (replace the package placeholder) or `rg --files frontend/src -g '*.test.ts'`. A filename match is not proof that the full user scenario is covered.
