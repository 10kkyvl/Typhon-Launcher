# Launcher patterns — which one is used where

The structural patterns this code base actually follows, one row each, with the command that finds
candidates. `typhon-architecture-keeper` checks a change against these rows; a person adding a package,
a service, a store or a component reads the rows of that area first. Properties of state, deletion,
locking and cancellation are in [INVARIANTS.md](INVARIANTS.md) and are not repeated here; wiring and
package tables are in [ARCHITECTURE.md](ARCHITECTURE.md).

Snapshot: 2026-11-27. Go rows from `dev`; frontend rows from the redesign line (`origin/2.0` and its
`v2/…` sub-branches), where the kit and its guards live: on `dev` the frontend predates them and only F1
and F7 have a test behind them.
The counts are a snapshot: run the command, do not quote the number.

Status of a row:
- **rule**: written in the instructions or enforced by a test or lint; a deviation is a finding.
- **norm**: followed in the code and first written down here; a deviation is a finding unless the
  change says why.
- **open**: two variants coexist and nobody chose; new code using either is not a finding. The keeper
  names the variant used; choosing one is the user's decision.

Sibling repositories (backend, site, bot) have their own maps in the workspace:
`../.agents/architecture/{backend,site,bot}.md`.

## Go (`main.go`, `internal/**`)

| # | Pattern | Status | Canonical example | Candidates |
|---|---|---|---|---|
| G1 | **Composition root.** Every service is constructed in `main.go` and registered there; callbacks are wired after all constructors. A service does not construct another service and does not call `application.Get()` in its constructor. | rule (ARCHITECTURE §4) | `main.go` (constructors, then `Set*` wiring, then `application.NewService`) | `grep -rn 'NewService(\|NewManager(' internal --include='*.go' \| grep -v '_test.go\|func New\|wine.NewManager\|NewServiceAt'` (empty today). Known exception, a setter called in a constructor: `install/service.go` calls `downloads.SetOriginCheck` |
| G2 | **Constructor twin.** `NewService()` resolves `settings.ConfigDir()` and delegates to a path-taking twin (`NewServiceAt`, `newServiceAt`, `newManagerAt`) that tests call with `t.TempDir()`. | norm (INVARIANTS mistake 14 states the test half) | `library/library.go`, `history/service.go`, `relocate/service.go` | a package with `func NewService` and no `At` twin |
| G3 | **Coupling between domain packages.** New coupling goes through a callback set with `Set*` in `main.go`, or a consumer-side interface (`*Port`, `busyChecker`) that `main.go` satisfies. A new import between `internal/*` domain packages needs the ARCHITECTURE §2 / §3 tables changed in the same work. The two forbidden edges are in AGENTS "Guardrails". | rule (ARCHITECTURE §2, AGENTS "Guardrails") | callbacks: `install/service.go` `SetBusyCheck`, `SetTitleResolver`; ports: `diskusage/service.go`, `cloudsaves/service.go`, `relocate` `busyChecker` | added imports in a range: `git diff <range> -- '*.go' \| grep '^+.*"typhon/internal/'`; the whole graph: `go list -f '{{.ImportPath}} {{join .Imports " "}}' ./internal/...`. The §2 / §3 tables are behind the code (they say `relocate` imports `updates`: it takes an interface; about thirty existing edges are not listed): an existing unlisted edge is map drift, not a finding against the change |
| G4 | **Setters.** A `Set*` wiring method on a registered service is `//wails:ignore` and takes the service mutex. | norm | `install/service.go` `SetBusyCheck` | `grep -rn 'func (.*) Set[A-Z]' internal \| grep -v _test`, then read the two lines above and the first line of the body |
| G5 | **Package layout.** `service.go` (state and the public API), `model.go` (types), `store.go` (disk, through `internal/storage` only), `client.go` (HTTP); `uicodes_test.go` and `store_integrity_test.go` beside them. A new subsystem inside a big service gets its own struct and file, not more fields on the service. | norm (go-internal.md states the last sentence) | `sources`, `updates`, `relocate` | a new package whose disk or HTTP code sits in `service.go` |
| G6 | **Lifecycle.** `ServiceStartup` derives the service context; the shutdown order is I-6. Constructor and startup errors leave only through `main.go::fatal`. | rule (INVARIANTS I-6, ARCHITECTURE §4) | `download/manager.go`, `install/service.go` | a goroutine or a network call started in a constructor |
| G6a | Where the authoritative state is loaded: in the constructor (`library`, `history`, `settings`, `theme`) or in `ServiceStartup` (`install`, `download`, `updates`, `sources`). | open | both | — |
| G7 | **Errors to the UI.** A user-facing failure carries a `uierr` code `domain.snake_case`; the frontend words it by code. A package that returns codes has `uicodes_test.go`, which scans its own sources against the TS table. | rule (I-15) for the code; norm for the test | `install/uicodes_test.go`; TS half: `frontend/src/lib/i18n/backendCodes.test.ts` | packages with codes and no test: `comm -23 <(grep -rl 'uierr\.\(New\|Wrap\)' internal --include='*.go' \| grep -v _test \| xargs -n1 dirname \| sort -u) <(ls internal/*/uicodes_test.go \| xargs -n1 dirname \| sort -u)` (a known backlog: a NEW package on that list is the finding) |
| G8 | **Events.** Every event is registered in `main.go` with `application.RegisterEvent[Payload]("name")`; the owning package emits it, outside its lock. | rule (ARCHITECTURE §5, INVARIANTS mistake 16) | `main.go::init`; `download/manager.go` | `grep -rn 'RegisterEvent' internal \| grep -v _test` (must be empty). Names and payloads against the frontend: `typhon-contract-keeper` |
| G8a | The emit helper: a plain `func emit` guarding `application.Get() != nil`, or a `var emit = func` that tests swap. | open (the plain function is the common one; the `var` form is a test seam of the kind G10 stops adding) | `install/service.go` (plain), `download/manager.go` (`var emit`) | — |
| G9 | **Platform split.** One file per variant of the same function, with complementary build tags: `_windows.go`, `_darwin.go`, `_devmock.go`, and a stub `_other.go` for the rest. `devmock` never compiles for Windows or with `production`; `qa` only for Windows and never with `production`. | rule (I-16) | `account/credential_devmock.go`; guards `internal/devmock/forbid_devmock.go`, root `qa_forbid.go` | `GOOS=windows GOARCH=amd64 go vet ./...`, `go vet -tags devmock ./internal/...`, `bash scripts/check-build-tags.sh` |
| G9a | The name of the non-special twin: `_other.go` or `_default.go`. | open (`_other.go` is the common one; `_default.go` is used where the twin is "not devmock / not qa" rather than "another OS") | `selfupdate/url_default.go` | — |
| G10 | **Test seams.** State through the `At` twin and `t.TempDir()`; time through a `now func() time.Time` field the constructor sets; the network through `httptest`. No new function field that only tests set, no new package-level `var x = func…` for tests to override, no `time.Sleep`. | rule for function fields and `time.Sleep` (go-internal.md, forbidigo); norm for the package-level `var` and the `now` field. The sweep itself is `typhon-invariant-keeper`'s | `savebackup/service.go` `now`; `install/service_test.go` `waitFor` | `git diff <range> -- '*.go' \| grep -E '^\+var [a-z][A-Za-z]* *= *func'`; a new struct field of function type with no production assignment |

## Frontend (`frontend/src`, the 2.0 line)

| # | Pattern | Status | Canonical example | Candidates |
|---|---|---|---|---|
| F1 | **Bindings stay behind services.** `bindings/` is imported by `lib/services/*`, which wrap every call behind `inWails` and turn failures into coded errors. No `.svelte` file imports bindings. | rule (frontend.md; `lib/services/bindingsContract.test.ts`, `serviceConventions.test.ts`) | `lib/services/social.ts` | `grep -rlE "bindings/typhon" frontend/src --include='*.svelte'` (must be empty); `.ts` importers outside `lib/services`: today `stores/{pendingLaunch,launchNavigation,gamemode}.ts` (calls), `lib/theme/apply.ts` and `lib/history/*` (types), test harnesses. A new name on that list is the finding |
| F2 | **Direction.** `routes/**` import `lib/**`; `lib/**` does not import `routes/**`; `lib/bigpicture/**` does not import `routes/**`; `overlay/**` imports `routes/friends/FriendRow.svelte` and nothing else from there. Stores, services and utils do not import components. | rule for the last sentence (`lib/testing/componentImports.test.ts`); norm for the rest | — | `grep -rnE "routes/" frontend/src/lib frontend/src/overlay --include='*.ts' --include='*.svelte' \| grep import \| grep -v '\.test\.ts'`. Known exceptions: the lazy loader `lib/navigation/showcase.ts`, harnesses in `lib/testing/`, `overlay/OverlayFriends.svelte` |
| F3 | **Who listens to Go.** `Events.On` lives in a store or a service, or in a screen's page controller (`*.svelte.ts`); a component does not subscribe. | norm | `lib/stores/downloads.ts`; `routes/game/gamePageData.svelte.ts` | `grep -rn "Events\.On" frontend/src --include='*.svelte'`. Known exception: `lib/bigpicture/components/GamePage.svelte`. The name is a constant, not a literal (frontend.md): `grep -rn "Events\.On('" frontend/src --include='*.ts' --include='*.svelte' \| grep -v test`; a literal in new code is the finding, the existing ones are drift |
| F4 | **The kit.** A control is a base part of `lib/components` (`Button`, `IconButton`, `TextField`, `TextArea`, `PathField`, `OptionList`, `Select`, `Toggle`, `Checkbox`, `Notice`, `EmptyState`, `Modal`, `ConfirmModal`, …), never a raw element with its own CSS. Each guard below is a source test; a new site passes it or is listed in it with a reason (never in `styles/*.test.ts`: frontend.md). | rule (frontend.md + the guards) | `routes/showcase/` shows every base part | run the guards: `rawButtonSites`, `noticeSites`, `noticeRetrySites`, `routes/fieldEdges`, `hintGuards` (no native `title`), `pageHeadings`, `Page.coverage`, `countBadgeSites`, `*.callers` (one way to hold a value, no spread, reasons passed down), `showcase.coverage` (a base-shaped component is in the showcase), `ThemeGuard` and `styles/*` (tokens only) |
| F5 | **Where state lives.** Shared, event-fed domain state: a `writable` store in `lib/stores/*.ts` with an `init*()` (some return their disposer: `initLibrary`, `initCollections`; `initSources`, `initDownloads` and `initLan` return nothing). One screen's own data and reads: a page controller `routes/<screen>/<screen>Page.svelte.ts` (runes). One component's own state: `$state` in the component. No rune state in `lib/stores`. A dialog with more than one responsibility keeps its state and actions in a factory `create<Dialog>(inputs)` (runes, getters for what it follows, created once in the dialog's init, closure state and no module-level rune state): `lib/components/installDialog.svelte.ts` (InstallModal), `lib/game/{compatSwitch,fileWrites,gameModeWrites}.svelte.ts` (GamePropertiesModal); beside the dialog or in the domain folder: open. One exception: `lib/game/fileWrites.svelte.ts` exports `fileWrites`, module-level rune state shared by every mount of GamePropertiesModal, because a file write that runs is a fact about the game that outlives the dialog that began it (a language switch, Big Picture or a new session remounts the dialog while it runs); each write records the mount that began it, only that mount says its outcome or blocks its own dismissal, and a write that never answers holds its game for the session. | norm (the page controller is what new screens use: settings, disk usage, catalog, game) | `lib/stores/sources.ts`; `routes/diskusage/diskUsagePage.svelte.ts` | a new store that only one screen reads; a screen whose reads sit in the `.svelte` file past the size limit |
| F6 | **A read has three states and a guard.** Loading, failed (a danger `Notice` with its `retry`, never an empty state), empty with its own words. An answer that arrives after a newer one, after the screen was left, after a dialog was reopened or under another account paints and says nothing: a counter is read before the request and compared after it. | rule for the failed state (frontend.md; `lib/stores/loadFailureScreens.test.ts`, `noticeRetrySites.test.ts`); norm for the counter | `lib/stores/lan.ts` (`heard`); `stores/collections.ts` | a `catch` that toasts and leaves the list empty; an `await` followed by an assignment with no comparison |
| F6a | The counter's name: `heard` (lists that Go also sends as events), `seq` / `generation` / `token` (plain requests), `opening` with `const heard = () => alive && at === opening` (dialogs reopened while an answer is out), or `LatestRequestGate` (`lib/bigpicture/latestRequest.ts`: Big Picture controllers and the desktop `SourceDetailsModal`, `SourceReleases`). | open | — | — |
| F7 | **Words by code.** The UI never shows Go's text: a domain table maps a code to a catalog key (`Record<code, MessageKey>`), ru and en have the same keys and placeholders. A new Go code needs its row. A reason said after an action goes through `actionErrorText` (`lib/library/errors.ts`: a clause code of `library` or `emulators` after the action, a sentence code alone; guard `lib/library/errors.composed.test.ts`). | rule (I-15; `lib/i18n/backendCodes.test.ts`, `errorTables.test.ts`, `catalogGuard.test.ts`) | `lib/install/installErrors.ts`; `lib/i18n/errors.ts` | `grep -rnE 'String\(err\)\|err\.message' frontend/src --include='*.svelte'` |
| F7a | The table file's name: `*Errors.ts`, `*Messages.ts` or `messages.ts`. | open | — | — |
| F8 | **Layers, focus, held controls.** Overlays go through `lib/layers` (Escape, outside press, Tab trap, focus return). A control that may hold focus when it becomes unavailable is held with a `reason` (`aria-disabled`, stays in the Tab order); a pressed control stays focused and `busy`. | rule (frontend.md) | `lib/components/Button.svelte`; `lib/layers/stack.ts`; `lib/utils/rowFocus.ts` | `grep -rn 'clickOutside' frontend/src --include='*.svelte'` (legacy helper, not for new code) |
| F9 | **Surfaces.** Big Picture (`lib/bigpicture/**`) and the overlay (`overlay/**`) are separate surfaces: they share stores, services, behaviour (frontend.md: one implementation) and a few display parts (`Artwork`, `ProgressBar`, `Avatar`), keep their own controls and styles, and are exempt from the kit guards. A store or service they share keeps its exports' names and meaning. A desktop dialog may use `lib/bigpicture/latestRequest.ts`. | norm | `lib/bigpicture/components/`, `overlay/` | a desktop screen's change that renames or re-types an export Big Picture reads: grep the export under `lib/bigpicture` and `overlay` |
| F10 | **Tests.** `*.dom.test.ts` for jsdom, plain `*.test.ts` otherwise (`lib/testing/domConvention.test.ts`); harness components in `lib/testing/`; a mounted test of a screen that talks to a backend replaces those services whole, and a `*.mocks.test.ts` guard keeps it so. | rule | `routes/friends/Friends.mocks.test.ts`; `lib/testing/gameDialogsTesting.ts`; `lib/components/{gameDialogs,settingsDialogs}.mocks.test.ts` (the `DIALOGS` lists) | a new screen folder with mounted tests and no guard |

## Across repositories

| # | Pattern | Status | Candidates |
|---|---|---|---|
| X1 | **The backend's error codes are copied by hand** into the launcher's tables (F7), the site's map and the bot's constants. A code added or renamed on the backend needs its row in each consumer that can receive it; an unknown code falls to a generic sentence. | norm (written only for the backend side, in its INVARIANTS) | the backend's `internal/httpapi/errors.go` `errorMessages` against `frontend/src/lib/services/*Messages.ts` |
| X2 | **Mirror types, no shared spec.** The launcher's request and response types for the backend are hand-written mirrors (`internal/social/model.go`, `internal/accountsync`, `internal/metadata/typhonapi/types.go`). The backend keeps both `/path` and `/v1/path` for released launchers and parses leniently; the launcher tolerates unknown fields. | norm | a launcher change that needs a field the released backend does not send, or the reverse |
| X3 | **Legal texts and release notes have one source: this repository.** The site copies them (`npm run sync:legal`, the changelog script). | rule (site INVARIANTS) | `typhon-legal-keeper` owns the check |
