# Typhon Launcher — System invariants

Required properties to preserve when changing code, with implementation pointers, relevant tests and known gaps. These are not a claim of complete enforcement: check the cited implementation and the actual assertions for the scenario at hand. Historical rationale is in `CLAUDE.md`; workflow authority and evidence policy are in AGENTS.md and [INDEX.md](INDEX.md). The last section lists the recurring mistakes agents make against these rules.

## Persistence

**I-1. One atomic writer.** Every state file is written through `internal/storage/doc.go::WriteAtomic` (CreateTemp in the same dir → write → chmod to the previous mode → fsync → checked Close → rename → dir fsync, Windows best-effort) or `storage.Save` (versioned envelope). `os.WriteFile` in production code outside `internal/storage` fails lint (test files are explicitly exempt) (`.golangci.yml` forbidigo).
Implementation / checks: forbidigo; every `persist` in every package. Tests: `storage/*_test.go`, per-package `store_integrity_test.go` (download, updates, relocate, sources, install, accountsync). Breaks when: a new package writes with `os.WriteFile`/`os.Create`, or a "temporary" file is written next to state without the temp→rename dance.

**I-2. Read error ≠ empty state.** `load` returns `(T, error)`; only `fs.ErrNotExist` means "start empty". Any other error (permissions, corrupt JSON, truncated file) makes the constructor fail (`main.go::fatal` exits) or `ServiceStartup` fail (Wails aborts `Run`, `main.go::fatal("run application")` exits), and nothing persists afterwards. No `persist` may run after a failed authoritative-state load. Rebuildable cache exception: `download/completion.go` quarantines corrupt `meta/piece-completion.json` before starting empty; do not generalize this to user state.
Implementation / checks: `settings/settings.go::load`, `library/library.go::load`, `install/store.go::load` + `service.go::ServiceStartup`, `download/store.go::load` + `manager.go::ServiceStartup`, `updates/service.go::ServiceStartup`, `relocate/service.go::NewServiceAt`, `sources/store.go`, `catalog/service.go::loadList`, `metadata/attempts.go`, `storage.Load`. Tests: `TestCorrupt*FailStartup*`, `TestMissing*StartEmptyAndSave` in `sources`, `install`, `download`, `updates`, `relocate`; `metadata/attempts_test.go::TestBrokenAttemptsFileStopsTheStore`. Breaks when: `if err != nil { return Defaults(), nil }`, `errors.Is(err, fs.ErrNotExist) || <anything else>`, or a new store that swallows parse errors.

**I-3. Memory and disk change together.** Mutate → persist → on failure roll memory back → return the error (it reaches the UI). Long-running services additionally flip a `*:degraded` event (`download`, `updates`, `relocate`, `sources`, `history`, `playlog`) instead of crashing; a later successful persist clears it. Documented background exceptions include `library/sessions.go::finishSession` (playtime persist has no caller to return to) and `download/manager.go::completeLocked`/`markFailed` (the new state is the safer landing); each has a comment.
Implementation / checks: `library.RegisterInstalled/RemoveGame/MarkUninstalled/finishSession`, `install/service.go::persistLocked` callers (`setStatus`, `Start`, `Retry`, `Dismiss`, `complete`…), `download/manager.go::Pause/Resume/ForceStart/dropLocked/AddTask`, `updates/service.go::mutate/check/prune/setJournal/clearJournal/registerRollback/emitVerify`, `relocate/service.go::transition/removeJob/registerJob`, `sources/service.go::settle/fail/IgnoreRelease` (`restoreReleasesLocked`), `settings/settings.go::persist`. Tests: `download/persist_failure_test.go` (11), `updates/degraded_test.go` (12), `relocate/degraded_test.go`, `install/persist_test.go`, `install/ownership_retry_test.go`, `sources/*RollsBack*`. Breaks when: `append/delete` before `persist` with a bare `return err`; emitting the event before the persist result; a new mutator without the rollback clause.

**I-4. Verification before deletion.** A source copy is removed only after the destination was verified by content hash (`internal/hashdir`, `install/fsops.go::verifyCopy`), never after a size comparison. `Sync` before delete.
Implementation / checks: `install/fsops.go::CopyDirVerified`, `MoveDir` (copy fallback), `service.go::recoverMovePartial`; `relocate/service.go::copyAndVerify` → commit → `cleanupItem`, `recover.go::recoverCleanup/recoverRepoint`; `download/repoint.go::moveTreeIfPresent`; `updates/apply.go::copyInstallAside/backupInPlace` (verified copies before writing into the live install). Tests: `install/fsops_test.go::TestVerifyCopyDetectsSameSizeDifferentContent`, `relocate/relocate_test.go::TestMoveGameVerifyFailureKeepsSource`, `relocate/audit_regression_test.go::TestRegressionRecoveryDeletesGoodSourceForBadTarget`, `download/audit_regression_test.go::TestRegressionRepointOccupiedTargetDeletesSource`. Breaks when: a "fast path" skips `hashdir.Verify`; a cleanup step is moved before the verify stage; recovery trusts a pre-crash verify.

## Atomicity and recovery

**I-5. Multi-rename operations are journaled and recovered at startup.** Any sequence of two or more renames on user data (update swap, patch merge, in-place update/repair, move, downloads repoint, self-update bundle swap) writes its intent to disk before the first rename and has a recovery routine in the owner's `ServiceStartup`. Error handlers alone do not count — the process may die between the steps.
Implementation / checks: `updates/apply.go::swapDirectories` (journal `swap` before rename), `runPatchChain` (journal `patch` before `MergeDirWithBackup`), `backupInPlaceSuffix` (journal `inplace` after the verified copy), `recoverJournals` at startup (`failJournalRecovery` keeps the journal); `relocate/service.go::transition` per stage + `recover.go::recoverAll`; `install/service.go::ServiceStartup` (`sweepPartial`, `recoverMovePartial`, resume watchers, `sweepRemovals`); `install/removal.go::stageForRemoval` (record in `removals.json` before rename); `download/repoint.go` re-entry branch. Tests: `updates/apply_recovery_test.go` (windows A–D, `TestSwapDirectoriesJournalsBeforeRename`, `TestApplyPatchChainCommitsEachPatchBeforeTheNext`), `relocate/recover_test.go::TestRecoverAtStage`, `install/startup_test.go`, `install/sweep_test.go`. Historical reported gaps (revalidate status before acting): `updates/apply.go::Rollback` and `selfupdate/bundle_darwin.go::swapBundle` do two renames without a journal (TYPHON-AUDIT-006/014). Breaks when: a new rename is added to an existing flow outside the journaled window; the journal write is moved after the first rename; a recovery branch clears the journal on failure.

**I-6. Resource ownership and lifecycle.** Every goroutine is counted in the owner's `WaitGroup` and takes a ctx derived from the service ctx; `context.Background()` only in `main` and tests (forbidigo). Spawning is refused once `closing` is set and decided under the same mutex as `wg.Add`. Shutdown order: closing flag → cancel jobs → cancel ctx → `wg.Wait` → final persist → close external resources (torrent client, completion db). Game processes are the one deliberate exception: `library.sessionWG` is not waited — games outlive the launcher. Child installer processes are killed on cancel (`TerminateJobObject`, cancel file, worker cancel marker). The cloud launch check is a goroutine of the service (`wg`, service ctx), not of the launch; a launch that stops waiting does not cancel a download that was proved necessary (`cloudsaves/launch.go::leaveCheck`).
Implementation / checks: `download/manager.go::spawnTrackedLocked/startTeardownLocked/ServiceShutdown`, `install/service.go::spawnLocked/baseLocked/notifyFinished/ServiceShutdown`, `updates/service.go::beginJob/ServiceShutdown`, `relocate/service.go::context/registerJob`, `library/sessions.go::ServiceShutdown`, `sources/service.go::context/notifyChanged`, `metadata/service.go::baseContext`. Tests: `download/goroutine_tracking_test.go`, `download/leakcheck_test.go::TestMain`, `download/no_ctx_fallback_test.go`, `install/notstarted_test.go`, `install/notify_test.go`, `updates/lifecycle_test.go`, `sources/*NotifyChanged*`, `metadata/*RefusesAfterShutdown*`. Breaks when: a bare `go func(){}()`; `if ctx == nil { ctx = context.Background() }`; a callback invoked after `Shutdown` that persists or drops a torrent; `Close` of a process handle from a goroutine other than the one in `wait()` (`install/elevated.go::handOffToWorker`, `broker_host.go::tendBroker`).

**I-7. Trust boundaries for external input.** Feed entries, archive/torrent entry names, manifest paths, UI-supplied paths and release URIs are validated before use (`..`, absolute, drive letters, `filepath.IsLocal`, length, allowed values). Self-update artifacts are accepted only after ed25519 signature and SHA-256 verification, re-checked at startup. Feed fetches refuse loopback/private hosts including after DNS and redirects. Bearer tokens travel only over https (loopback exempt); `CheckRedirect` re-validates every hop and strips `Authorization` on host change.
Implementation / checks: `install/safety.go::safeJoin`, `download/torrent.go::validateInfo/isSafeTorrentPath`, `selfupdate/bundle_darwin.go::safeJoin`, `selfupdate/sign.go` + `service.go::ServiceStartup` (`VerifyFile`), `sources/feed/guard.go`, `feed/limits.go`, `account/config.go::ValidateBaseURL`, `account/client.go::CheckRedirect`, `install/broker.go::validateBrokerSpec`, `install/discovery_shared.go::readLimited`. Tests: `install/safety_test.go`, `install/broker_test.go::TestValidateBrokerSpecRejectsEscapes`, `download/torrent_test.go` path tests, `sources/feed/guard_test.go` (`TestRedirectToPrivateAddressIsBlocked`…), `selfupdate/bundle_darwin_test.go`, `account/*BaseURL*`. Breaks when: a new file type is extracted without `safeJoin`; a new HTTP client is built without `account.CheckRedirect`/timeout; a fetched size is trusted without `io.LimitReader`.

## Identity

**I-8. Installed release identity is provenance, not similarity.** A library game is linked to a release by `SourceID` + `DistributionID` (legacy: exact `ReleaseID`), carried from `sources.Release` → `download.Origin` → `install.Installation.Origin` → `library.InstalledGame` → `library.Game`. Update detection (`updates/resolver.go::sameDistribution`) ignores title/repacker/version similarity entirely; a release from another source or distribution is never an update. `library.Game.ID` is the launcher-local key; `CanonicalGameID` is the catalog id; `Origin.LibraryID` vs `Origin.GameID` are different keys (`download.ByOrigin` matches either).
Implementation / checks: `install/flow.go::register` (payload incl. `DistributionID`, `ReleaseUploadedAt` — uncommitted), `library/library.go::RegisterInstalled` (a reinstall with a `ReleaseID` overwrites repacker/version; without one inherits — open finding TYPHON-AUDIT-003), `updates/resolver.go`, `updates/plan.go::validatePlan/releaseBelongsToPlan`, `updates/service.go::bindLegacyDistribution`, `sources/import.go::merge` (release identity by `DistributionID`). Tests: `updates/resolver_test.go` (21), `updates/provenance_test.go`, `sources/import_test.go::TestMergeDistribution*`, `library/*_test.go` registration tests. Breaks when: matching by normalized title is added "to be helpful"; `DistributionID` is dropped when copying `Origin`; a new install path registers a game without carrying `Origin`.

**I-9. The install marker is the on-disk identity.** `<InstallDir>/.typhon-install.json` (`library/marker.go`) is written on registration and relocation and read by discovery (re-adopt moved folders), and by removal (ownership proof for legacy records). It is a copy of library metadata, never the source of truth for playtime/favorites.
Implementation / checks: `library/discovery.go::markInstalled`, `library/relocate.go::Relocate`, `discovery/scan.go::adopt/refresh`, `install/removal.go::removalPlan`. Tests: `library/marker_test.go`, `discovery/scan_test.go`. Breaks when: a new field is added to `Game` that discovery needs but `markerFor` does not copy.

**I-10. Destructive filesystem boundaries.** The launcher deletes only: install dirs it owns (`Installation.Owned`/`OwnedDestination`, `controlled(Type)`, or a marker), its own staging/backup dirs (`.partial`, `.staging`, `.previous*`, `.replaced`, `.patch-backup`, `.removing`, `.repoint-staging`), download payload roots computed from the real layout, and CrossOver bottles carrying `typhon-bottle.json`. It never deletes: a dir that existed before the installer ran, a dir an installer tree may still write to (`install.installer_not_confirmed_stopped`), the shared Steam bottle, a path that is a volume root/relative/symlink, or library entries' files on `library.RemoveGame`.
Implementation / checks: `install/removal.go::removableDir/removalPlan/sweepRemovals` (refuses paths without `.removing`), `install/flow.go::discardSilent`, `install/fsops.go::checkNotNested/destAvailable`, `download/manager.go::DeleteData` (flat via `os.OpenRoot`), `removeContent`, `updates/service.go::stagingDir/previousDir` (reject empty), `relocate/service.go::validateTarget`, `wine/manager.go::Remove` (marker required), `library/library.go::RemoveGame` (archive + exclude only). Tests: `install/removal_test.go`, `install/resume_test.go::TestDiscardSilentKeepsDirectoryWhenInstallerNotConfirmedStopped`, `download/audit_regression_test.go::TestRegressionDeleteFlatDataLeavesPayload`, `relocate/relocate_test.go::TestMoveGameRejectsBadTargets`, `wine/*_test.go`. Known gap: `download/manager.go::removeContent` derives the root from `Destination/Name` and ignores `Flat` (called from `DeleteData` and `discard`; the non-in-place unfinished-cancel path needs its own reachability analysis before claiming a reproducible flat-layout bug). Breaks when: a delete is added with a root built from a display name; ownership is inferred from "dir is inside GamesPath"; a cleanup runs while `closing`.

## Concurrency and cost

**I-11. Check-and-act under one lock.** "Is this hash/game/dir busy?" and the action that depends on it happen in the same mutex hold: infohash reservations (`download/reuse.go::reserveHash/reserveHashExcept`, `FetchMetadata`, `StartDownloadFrom`, `settleRestored`), install `Cancel`/`Retry` worker-alive checks, `relocate/service.go::registerJob`, `updates/service.go::beginJob` slots, `library.PlayGame` running check (`starting[id]` counts), `cloudsaves/launch.go::joinCheck` (join the game's running check or start it, and the `fetching` gate, in one `Service.mu` hold).
Tests: `download/toctou_test.go`, `download/fetch_cancel_test.go`, `install/resume_live_test.go::TestRetryRejectedWhileWorkerStillAlive`, `cloudsaves/launch_edges_test.go::TestLaunchesRacingPastTheGatesShareOneCheck`. Breaks when: a check is hoisted out of the lock to "avoid holding it during I/O" without moving the I/O instead.

**I-12. Expensive work outside locks, once per flow.** Tree walks, `DirSize`, `Inspect`, `InspectReuse`, `hashdir.Build/Verify`, engine polls run outside the service mutex and their results are passed down (`install/inspect.go` two walks max; `updates/plan.go::inspectReuse` once per `buildPlan`; `updates/saves.go::locateSaves` at plan time only; `relocate/service.go::cleanupItem` does not re-verify). No syscalls inside sort comparators (`updates/order.go` sorts pre-parsed `Candidate`s; `hashdir` sorts strings). `SessionWatcher` callbacks are invoked under the library lock and must return immediately (presence/online/heartbeat only enqueue). Launch hooks run between `prepare` and `start` with the library lock released; a hook that must stop a launch returns `library.LaunchBlockedError`, any other error is only logged (`library/sessions.go::play`). `cloudsaves/launch.go::runCheck` lists and hashes outside `opMu` and acts under it; `loadState` and `treeOf` read the state file and the hash cache outside `Service.mu`.
Tests: `install/service_test.go` timing-sensitive tests, `download/manager_test.go`. Historical reported gaps (revalidate status): directory size measured under the lock in `RegisterInstalled` (TYPHON-AUDIT-008). TYPHON-AUDIT-007 is closed: `library/sessions.go::play` reserves `starting[id]` and runs `prepare`, the hooks and `start` with `s.mu` released (`library/launch_hook_test.go::TestLaunchHookRunsBetweenPrepareAndStartOutsideTheLock`). Breaks when: a new `filepath.WalkDir` or `os.Stat` loop is added inside `s.mu.Lock()`; a comparator calls `os.Stat`.

## Semantics

**I-13. Cancellation semantics.** Cancel = ctx cancel of the job; a job that observes its own cancellation ends as `cancelled`, not `failed` (download `discard`, install `fail` cancelled branch → `markCancelledLocked`, updates → `update_available` + "прервано", relocate `failOrCancel`). Cancelling never deletes verified data already in place (relocate after commit, updates after `registerVersion`). An installer whose process tree could not be confirmed dead leaves status `failed` and the directory intact. Shutdown is not cancellation: in-flight teardowns are skipped, torrents are not dropped individually, games are not killed.
Implementation / checks: `install/service.go::Cancel/fail`, `install/elevated.go::runElevated`, `download/manager.go::discard/startTeardownLocked`, `updates/apply.go::StartUpdate` outcomes, `relocate/service.go::Cancel/failOrCancel`. Tests: `install/*cancel*`, `install/resume_test.go`, `download/goroutine_tracking_test.go::TestDeleteDataSkipsTeardownWhileClosing`, `updates/lifecycle_test.go`, `relocate/relocate_test.go` cancel cases, `hashdir/hashdir_test.go` ctx tests. Breaks when: `errors.Is(err, context.Canceled)` is checked after the error was wrapped without `%w`; a cancelled job is reported through the `failed` branch with a user-visible error.

**I-14. Idempotency.** `OnCompleted` fires once per download (`beginJob` gating in `download/manager.go::verifyCompletion`); each patch registers its version before the next starts (`updates/apply.go::runPatchChain::registerVersionAs`), so a re-run of a chain resumes from the recorded version; `install.Retry` on a `crashFinalizable` record re-finalizes instead of re-extracting; relocate recovery is stage-idempotent (`recoverRepoint` may run again); the broker consumes `spec.json` before running it (`install/broker.go::RunBroker`) so a crash cannot run an installer twice; the worker `Run` token makes stale `Done:true` states unusable (`install/elevated.go`). Tests: `download/manager_test.go::TestCompletionNotifiesInstaller`, `updates/apply_recovery_test.go::TestApplyPatchChainCommitsEachPatchBeforeTheNext`, `install/elevated_test.go::TestRunElevatedIgnoresTheStateOfThePreviousRun`, `install/broker_test.go`. Breaks when: a completion callback is added outside the job gate; `registerVersionAs` is deferred to the end of a chain; worker state is read without comparing `Run`.

**I-15. Errors keep their cause and never become defaults.** No `if v, err := f(); err == nil { x = v }`; no `slog.Error(...); return nil`; no `return 0/""/true` on error; no `_ =` on `Remove`/`Close`/`WalkDir` without a "why" comment. Distinct causes are distinct `uierr` codes wrapped with `%w`; `uierr.Code` reads the innermost code. "Unknown" is an explicit flag (`SizeUnknown`, `UninstallUnknown`, `PathUnknown`, `CreatedAtUnknown`, `Unknown` in patch costs), never a zero value. `CanAutoInstall`, `Repairable`, `Owned` are set only after the data behind them was obtained without error. A `verify`/`check` function verifies what its name says (`checkSpace` fails when free space is unknown; `verifyInstall` distinguishes unreadable from empty).
Implementation / checks: linters `errcheck`, `nilerr`, `errorlint`; `install/service.go::checkSpace/verifyInstall`, `install/inspect.go` (`CanAutoInstall` sites), `updates/verify.go::applyReuseReport/failVerify`, `library/watch.go::detectTick` (scan error ⇒ no session change), `download/manager.go::checkFreeSpace`. Tests: `install/*::TestCheckSpaceFailsWhenFreeSpaceIsUnknown`, `TestVerifyInstallDistinguishesReadErrorFromEmpty`, `TestInspectUnreadableArchiveIsNotAutoInstallable`, `updates/verify_test.go::TestRepairRefusesWithoutTorrentVerdict`, and `uicodes_test.go` in install, download, updates, relocate, sources, metadata, library, settings, catalog, lan, selfupdate. Breaks when: the archive package (already coarse: password/CRC/volume collapse into `install.unsupported_archive`) is extended without new codes; a new `uierr` code lacks its frontend table entry.

**I-16. Build-tag isolation.** `devmock` code never reaches a Windows or `production` binary (`internal/devmock/forbid_devmock.go`; CI asserts both build failures; the release workflow greps `bin/typhon.exe` for `TYPHON_DEVMOCK_ENABLED`). Platform files follow `_windows.go` / `darwin && !devmock` / `devmock && !windows` / `!windows && !devmock [&& !darwin]`; a darwin-and-Windows helper uses `windows || (darwin && !devmock)`. Windows-only tests are `*_windows_test.go`; select other tests by their build tags and runtime prerequisites; permission/symlink limits, unavailable runtime dependencies and explicit live gates can cause skips (see TEST_MAP).
Tests: CI `ci.yml` jobs "Cross-build for Windows must reject the devmock tag", "Production tag must reject the devmock tag"; `go run ./tools/lintbaseline -tags devmock`. Breaks when: a mock file forgets `!windows`; a `_other.go` stub is not excluded on darwin after a darwin implementation is added (dead code fails lint).

**I-17. One source of truth per concept.** Version normalization: `internal/version` (`updates/graph.go::VersionKey` wraps it); archive extensions and installer engines: `internal/install/archive.go`, `engine.go`; title normalization: `internal/titles`; library root layout: `settings.derivePaths`; feed limits: `sources/feed/limits.go`; error text prefix for persist failures: `install.errPersistPrefix`; the `SessionWatcher` interface: `library`; discovery spec: `install/discovery_shared.go` (`runSpec.discovery()`/`workerSpec.discovery()` → one `attemptDiscovery`). Breaks when: a second parser/normalizer is written locally "for now".

## Common agent mistakes (seen in this repo's history and audits)

1. **Error into the void.** `slog.Error(...)` then `return nil` / `continue`, or `_ = os.Remove(...)`. Symptom: a file silently missing, a job "completed" with nothing on disk. Fix: return the error, or a typed `Unknown` flag, or a one-line "why" comment on the discard.
2. **Half-fixed load/save.** Distinguishing `ErrNotExist` in `load` but leaving a `persist` reachable after the failed load (or vice versa). Always verify both halves: `load` returns the error *and* the service cannot persist afterwards (`store_integrity_test.go` pattern: corrupt file → startup fails → file bytes unchanged).
3. **Rollback that only handles the happy crash.** Adding an error handler around two renames and calling it recovery. The process dies *between* renames; the recovery must live in `ServiceStartup` and be tested by simulating the on-disk state after each step (`apply_recovery_test.go` windows A–D).
4. **Size instead of hash.** "Compare sizes, then delete the source." Name such a function `verifySizes` and never delete on its result; use `hashdir`.
5. **Skipping non-regular files, then deleting the source.** `if !d.Type().IsRegular() { return nil }` before a `RemoveAll(src)` loses symlinks silently. Copy symlinks (`Readlink`/`Symlink`), error on the rest.
6. **TOCTOU by "not holding the lock during I/O".** Check under lock → unlock → act. Reserve under the lock (`reserveHash`), do the I/O, then record the outcome under the lock and release the reservation.
7. **Untracked goroutine.** `go func()` without `wg.Add` and without a service ctx; or `wg.Add` outside the mutex that `Shutdown` uses to decide to wait. It persists after shutdown, drops a torrent after the client is closed, or leaks (`download/leakcheck_test.go` catches leaks package-wide).
8. **Expensive work under the mutex.** `DirSize`/`WalkDir`/`Inspect`/engine polling inside `s.mu.Lock()`, or the same walk twice in one flow. Compute outside, pass results in.
9. **Default-on flags.** `CanAutoInstall = true`, `Repairable = true`, `Owned = true` set before the supporting data was read without error.
10. **Collapsing causes.** Mapping every archive failure to `unsupported`, every `downloads.Get` error to "download failed", `!ok || len(URIs)==0` to one error. Each cause gets a `uierr` code and a frontend table entry.
11. **Destructive root from a name.** Deleting `Destination/Name` when the real layout is flat/in-place/`BestName()`; deleting a folder because it lies under `GamesPath`; deleting a dir referenced by a live install job.
12. **Forgetting the frontend half.** A new `uierr` code, event or struct field without the TS table/type/store change; `uicodes_test.go` catches codes, nothing catches a missing event subscription except the live window.
13. **Trusting the installer/torrent report.** Exit code 0 is not proof of output (`silentDestination` re-locates); a torrent describing an installer package is not a verdict about the installed files (`torrentVerdict`); directory size is an estimate (`updateProgress` caps at 0.99).
14. **Testing with the user's real state.** Constructors have `NewServiceAt(dir)` for `t.TempDir()`; `prepareRuntime`/`releaseRuntime` must be stubbed or real CrossOver bottles appear; forged worker state without the `Run` token hangs the test for 10 minutes; `t.Skip`/`t.Fatal` while holding a mutex that cleanup needs deadlocks.
15. **Re-reading validated input.** Re-opening `spec.json` after `validateBrokerSpec` reopens the substitution window; pass the validated struct.
16. **Emitting under the lock.** `emit` reaches Wails; copy a snapshot, unlock, emit.
17. **"Fixed" without evidence for the reported scenario.** For a behavioural bug, use a meaningful regression that distinguishes the old and corrected behaviour, including the relevant component boundary. Choose applicable negative cases (missing file, permissions, corrupt JSON, cancellation, partial write, symlink, empty input); do not mandate all of them or a test-first ritual for unrelated trivial edits. State live/platform checks that remain unavailable.
