# Охота на баги: соннеты ищут, главная сессия принимает

Главная сессия — диспетчер и приёмщик. Она режет скоуп, раздаёт его охотникам на Sonnet,
ждёт, отдаёт находки проверяющему, читает только процитированные строки и пишет отчёт.
**Пока охотники работают, главная сессия код не читает** — это удваивает стоимость и
не добавляет находок. Правок в этом скилле нет: результат — отчёт, чинить — отдельная задача.

Шаблоны промптов — в `prompts.md` рядом; копировать, подставлять, не сочинять заново.

## Шаг 0. Скоуп и бюджет

Пакет не назван — скоуп выбирается по просьбе, не «весь модуль»:

| Просьба | Скоуп |
|---|---|
| «перед релизом», «после мержа», «что накодили» | файлы из `git diff --name-only $(git describe --tags --abbrev=0)..HEAD -- '*.go'` без тестов, сгруппированные по пакетам |
| «в проекте», «вообще», «весь лаунчер» | пакеты из инвариантов I–III: `storage install download updates relocate library sources settings` — первыми; остальные в отчёт как «не покрыто», следующий заход по просьбе |
| диф или ветка названы | `git diff --name-only <база>..HEAD`, охотник читает диф и вызывающие места |

Скоуп больше 2000 строк — сказать пользователю, сколько заходов нужно, и сделать первый.

```bash
for p in <пакеты>; do echo "$(cat $p/*.go | grep -v _test | wc -l) $p"; done   # строк без тестов
```

| Строк в скоупе | Охотников | Как делить |
|---|---|---|
| до 500 | 2 | одни файлы, разные линзы: A — ошибки и состояние (принцип, инварианты I–III), B — гонки, пути, ресурсы (IV–VII) |
| 500–2000 | 3 | по файлам, наборы не пересекаются |
| больше | 4 | по пакетам; остаток — в отчёт как «не покрыто» |

Больше четырёх — только если пользователь просит. Охотник дорог не числом, а объёмом:
шаблон ограничивает его в вызовах и длине отчёта, эти лимиты из промпта не вырезать. Диф вместо пакета: скоуп — файлы из
`git diff --name-only`, охотник читает диф и вызывающие места.

## Шаг 1. Охотники

Все вызовы `Agent` одним сообщением, `subagent_type: "general-purpose"`, **`model: "sonnet"`**,
промпт — «Охотник» из `prompts.md` с подставленными файлами и линзой. Охотник возвращает
не больше шести находок в формате из шаблона; без `файл:строка` и без сценария отказа
находка не принимается.

## Шаг 2. Ждать

Сразу после отправки охотников — одна команда `go vet <скоуп> && go test <скоуп>`, и ход
заканчивается фразой «жду охотников». Каждый следующий ход до их возврата стоит денег и не
даёт ничего: не открывать файлы скоупа, не читать вызывающие места, не запускать линт,
`git log`, `git status`, `ListAgents`. Отчёты охотников приходят сами, уведомлением.

## Шаг 3. Проверяющий

Проверяющий обязателен и в число охотников не входит: «пара соннетов» и «два субагента» в
просьбе пользователя — это два охотника плюс проверяющий. Без проверяющего отчёт — это
гипотезы охотников, а не находки.

Находки всех охотников склеить, дубли объединить, отдать **одному** Sonnet-проверяющему
(промпт «Проверяющий» из `prompts.md`; больше восьми находок — два проверяющих). Он
обязан попытаться опровергнуть каждую и вернуть вердикт: `CONFIRMED` (с доказательством:
трасса вызовов `файл:строка` либо тест, который упал), `REJECTED` (почему) или `UNCLEAR`.
Тест-доказательство пишется в файл `zz_hunt_test.go` внутри пакета и удаляется до возврата.
После проверяющего: `git status --porcelain | grep zz_hunt` — пусто, иначе удалить самому.

## Шаг 4. Приёмка

На каждую `CONFIRMED` — один `Read` процитированных строк (`offset`/`limit`, не весь файл).
Строки не соответствуют утверждению — находка уходит в `REJECTED` с пометкой «приёмка».
Больше ничего не читать.

## Шаг 5. Отчёт

Первая строка — итог: сколько подтверждено, сколько отклонено, что не покрыто. Затем
таблица подтверждённых: `файл:строка`, инвариант из CLAUDE.md, сценарий отказа одной
фразой, чем доказано. Затем отклонённые — по одной строке с причиной. Затем `UNCLEAR` и
непокрытые файлы. Правок не предлагать и не делать; на «почини» — отдельная задача по
superpowers:test-driven-development, по одной находке.

## Что не находка

- Стиль, имена, отсутствие комментария, «можно проще».
- Гипотеза без сценария «вход/состояние → неверный результат».
- То, что ловит `golangci-lint run ./...` — линт запускается, не пересказывается.
- Поведение, прямо описанное в комментарии «почему» рядом с кодом, если нет инварианта против.

## Частые ошибки

- Главная сессия «пока ждёт, сама прочитала оба пакета» — половина бюджета, ноль новых находок.
- Главная сессия «пока ждёт» гоняет `git log`, `git status`, `ListAgents` — каждый ход платный, охотники от этого не ускоряются.
- Ранг охотника (`ВАЖНО`) принят на веру без проверяющего — в отчёт уходят гипотезы.
- Бюджет кончился до отчёта — охотников было больше, чем таблица разрешает, или читался код.
- Охотник без списка файлов и линзы — возвращает пересказ пакета вместо находок.
- Проверяющий оставил `zz_hunt_test.go` — хук линта и `git status` покажут чужой файл.
