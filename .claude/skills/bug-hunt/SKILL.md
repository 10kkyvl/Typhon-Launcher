# Охота на баги: соннеты ищут, главная сессия принимает

Главная сессия — диспетчер и приёмщик. Она режет скоуп, раздаёт его охотникам на Sonnet,
ждёт, отдаёт находки проверяющему, читает только процитированные строки и пишет отчёт.
**Пока охотники работают, главная сессия код скоупа не читает** — это удваивает стоимость и
не добавляет находок. Правок в этом скилле нет: результат — отчёт, чинить — отдельная задача.

Шаблоны промптов, линзы и шкала критичности — в `prompts.md` рядом; копировать, подставлять,
не сочинять заново.

## Шаг 0. Скоуп и бюджет

Скоуп — это Go (`*.go` без тестов) **и** фронтенд (`frontend/src/**/*.{ts,svelte}` без
`*.test.ts` и `bindings/`). Пакет не назван — скоуп выбирается по просьбе, не «весь модуль»:

| Просьба | Скоуп |
|---|---|
| «перед релизом», «после мержа», «что накодили» | `git diff --name-only $(git tag --sort=-creatordate | head -1)..HEAD -- '*.go' frontend/src` без тестов (не `git describe`: релизный тег висит на мерж-коммите в main и из dev недостижим, describe вернёт древний тег и скоуп раздуется втрое); Go — по пакетам, фронтенд — по каталогам `stores`/`services`/`components`/остальное |
| «в проекте», «вообще», «весь лаунчер» | пакеты из инвариантов I–III: `storage install download updates relocate library sources settings` — первыми; затем `frontend/src/lib/stores` и `services`; остальное в отчёт как «не покрыто», следующий заход по просьбе |
| диф или ветка названы | `git diff --name-only <база>..HEAD`, охотник читает диф и вызывающие места |
| «фронтенд», «в окне», «Svelte» | `frontend/src/lib/<каталог>` плюс компоненты, которые его импортируют |

Скоуп больше 2000 строк — сказать пользователю, сколько заходов нужно, и сделать первый.

```bash
for p in <пакеты>; do echo "$(cat $p/*.go | grep -v _test | wc -l) $p"; done   # Go, строк без тестов
find frontend/src/lib/<каталог> -name '*.ts' -o -name '*.svelte' | grep -v test | xargs wc -l | tail -1
```

| Строк в скоупе | Охотников | Как делить |
|---|---|---|
| до 500 | 2 | одни файлы, разные линзы: Go — A и B; фронтенд — C дважды с разными файлами, либо A/B + C, если скоуп смешанный |
| 500–2000 | 3 | по файлам, наборы не пересекаются; фронтенд-файлы — своему охотнику с линзой C |
| больше | 4 | по пакетам/каталогам; остаток — в отчёт как «не покрыто» |

**Потолок — 600 строк на охотника.** Кусок больше — резать дальше или в «не покрыто»,
а не поднимать бюджет вызовов в промпте: 25 вызовов рассчитаны на 600 строк, на 1000
охотник обрывается посреди трассировки и отчёт выходит короче, чем кажется по таблице.
Больше четырёх охотников — только если пользователь просит.

## Шаг 1. Охотники

Все вызовы `Agent` одним сообщением, `subagent_type: "general-purpose"`, **`model: "sonnet"`**,
промпт — «Охотник (Go)» или «Охотник (фронтенд)» из `prompts.md` с подставленными файлами
и линзой. Охотник возвращает не больше шести находок в формате из шаблона; без
`файл:строка` и без сценария отказа находка не принимается. Критичность охотника —
предложение, решает проверяющий.

## Шаг 2. Ждать

Сразу после отправки охотников — одна команда проверок по скоупу: Go —
`go vet <скоуп> && go test <скоуп>`; фронтенд — `cd frontend && npm run check && npm test`.
Затем ход заканчивается фразой «жду охотников». Отчёты приходят сами, уведомлением.

Пока охотники работают, **не читать код скоупа и вызывающие места** и не поллить
охотников (`ListAgents`, `git status`, `git log` ради «а вернулись ли»). Работа вне скоупа —
поправить CLAUDE.md, ответить на вопрос пользователя, мелкая правка в другом месте —
разрешена: охотникам она не мешает и стоит дёшево.

## Шаг 3. Проверяющий

Проверяющий обязателен и в число охотников не входит: «пара соннетов» и «два субагента» в
просьбе пользователя — это два охотника плюс проверяющий. Без проверяющего отчёт — это
гипотезы охотников, а не находки.

Находки всех охотников склеить. **Дубли клеить по корневой причине** — одна пропущенная
проверка, одна функция, один неверный инвариант — а не по `файл:строка`: при трёх охотниках
на соседних файлах одна причина приезжает трижды в разных формулировках и с разными
строками. В склеенной находке перечислить все места. Отдать **одному** Sonnet-проверяющему
(промпт «Проверяющий» из `prompts.md`; больше восьми находок — два проверяющих). Он обязан
попытаться опровергнуть каждую и вернуть вердикт: `CONFIRMED` (с доказательством: трасса
вызовов `файл:строка` либо тест, который упал) **и критичность по шкале из `prompts.md`**,
`REJECTED` (почему) или `UNCLEAR`.
Тест-доказательство пишется в `zz_hunt_test.go` внутри пакета (фронтенд —
`frontend/src/lib/zz_hunt.test.ts`) и удаляется до возврата. После проверяющего:
`git status --porcelain | grep zz_hunt` — пусто, иначе удалить самому.

## Шаг 4. Приёмка

На каждую `CONFIRMED` — один `Read` процитированных строк (`offset`/`limit`, не весь файл).
Строки не соответствуют утверждению — находка уходит в `REJECTED` с пометкой «приёмка».
Критичность проверяющего можно понизить с пометкой «приёмка», повысить — нет.
Больше ничего не читать.

## Шаг 5. Отчёт

Первая строка — итог по шкале: `КРИТ n, ВАЖНО n, СРЕДНЕ n; отклонено n; не покрыто …`.
Затем таблица подтверждённых, КРИТ первыми: критичность, `файл:строка`, инвариант из
CLAUDE.md или критерий из `prompts.md`, сценарий отказа одной фразой, чем доказано. Затем
отклонённые — по одной строке с причиной. Затем `UNCLEAR` и непокрытые файлы. Правок не
предлагать и не делать; на «почини» — отдельная задача по
superpowers:test-driven-development, по одной находке, КРИТ первыми.

## Что не находка

- Стиль, имена, отсутствие комментария, «можно проще».
- Гипотеза без сценария «вход/состояние → неверный результат».
- То, что ловит `golangci-lint run ./...` или `svelte-check` — они запускаются, не пересказываются.
- Поведение, прямо описанное в комментарии «почему» рядом с кодом, если нет инварианта против.
- «Недостижимая ветка» или «дублирующая реализация» между файлами с разными build-тегами
  (`_windows`, `_darwin`, `_other`, `_devmock`): это разные сборки одной функции, в одну
  сборку попадает одна. Расхождение *поведения* между ними при одном входе — находка.

## Частые ошибки

- Главная сессия «пока ждёт, сама прочитала оба пакета» — половина бюджета, ноль новых находок.
- Главная сессия «пока ждёт» поллит охотников через `git status` и `ListAgents` — они от этого не ускоряются.
- Критичность охотника принята на веру без проверяющего — в отчёт уходят гипотезы.
- Дубли склеены по строке, а не по причине — одна ошибка в отчёте трижды, проверяющий тратит бюджет трижды.
- Охотнику отдали 1000 строк с бюджетом 25 — отчёт оборван, «не покрыто» не отмечено.
- Фронтенд не попал в скоуп, потому что диф брали по `'*.go'` — половина релиза не проверена.
- Охотник без списка файлов и линзы — возвращает пересказ пакета вместо находок.
- Проверяющий оставил `zz_hunt_test.go` / `zz_hunt.test.ts` — хук линта и `git status` покажут чужой файл.
