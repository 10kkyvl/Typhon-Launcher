# Ручная установка с правами администратора доходит до мастера

До d149bae любая ручная установка установщиком, просящим UAC, падала сразу с «путь
состояния установки не задан», а UI показывал «не удалось выполнить операцию». Тест кода
закрывает протокол воркера, но не настоящий UAC и не окно мастера поверх лаунчера.

## Подготовка

- Есть завершённая загрузка exe-установщика неизвестного движка или упавшая установка
  (в `installations.json` запись со `status: failed`). Нет — `ПРОПУЩЕН`.
- Отметка времени в логе.

## Шаги

1. `click 'Загрузки'` (или карточка игры) → найти установку → `click 'Повторить'`
   либо `click 'Установить вручную'`.
   ожидание: в логе `msg="installer requires elevation"` и **нет** строки
   `путь состояния установки не задан` / `install.worker_state_missing`.
2. ожидание: в каталоге состояния появился `worker-<id>.log` или spec-файл воркера
   (`Get-ChildItem $env:APPDATA\Typhon -Recurse -Filter "worker-*"`).
3. ЧЕЛОВЕК: подтвердить UAC. Агент останавливается здесь и пишет, что окно UAC появилось
   (процесс `consent.exe` есть в `Get-Process`).
4. ЧЕЛОВЕК: пройти мастер установщика.
   ожидание после: запись в `installations.json` со статусом `installed` (или
   `waiting_for_user`, пока мастер открыт), игра видна в «Установлено».
5. Отмена: при открытом мастере нажать «Отмена» в лаунчере.
   ожидание: установщик закрыт, статус `cancelled`, в логе нет `panic`.

## Доказательства

- Скриншот модалки установки до и после шага 1.
- Строки лога шага 1 дословно.

## Уборка

Если игра поставилась только ради проверки — удалить её через лаунчер (это шаг ЧЕЛОВЕК:
деинсталлятор тоже просит UAC).
